## What “low-confidence fallback” means

You already have the right idea:
1. Fast rule-based layer first
2. Semantic search second
3. If both are uncertain, send it to an LLM

That last step is the fallback.

---

## How to keep a threshold

Think of confidence as a score from `0` to `1`.

- `1.0` = very sure
- `0.0` = totally unsure

Example rule:
- If semantic search score > `0.8`, trust it
- If score is between `0.4` and `0.8`, maybe use fallback
- If score < `0.4`, definitely use fallback

That number is the threshold.

---

## How to log fallback decisions

Logging means saving a short record every time the fallback is used.

Example fields:
- user query
- semantic score
- chosen action
- whether fallback happened
- time taken

This gives you data later, so you can answer:
- “Why did Janus use the LLM here?”
- “Is the threshold too low or too high?”

A simple log row might look like:

```python
log = {
    "query": user_query,
    "semantic_score": score,
    "used_fallback": True,
    "fallback_method": "llm_check",
    "timestamp": now(),
}
```

Later you can inspect these logs and tune the threshold.

---

## What is a “fallback budget”?

A fallback budget is just a limit:

- limit how long the fallback can run
- limit how many fallback calls you allow
- limit how much cost or tokens you spend on fallback

Why it matters:
- If the fallback LLM takes 10 seconds, users wait too long
- So instead of “try forever”, you say “try up to 2 seconds”
- If it still hasn’t answered, return a safe response

That keeps your system responsive.

---

## Simple version you can build now

1. Calculate score from semantic search
2. If score >= `0.8`, use semantic result
3. Else:
   - call LLM fallback
   - but only if fallback is enabled
   - and only if time/cost limit is not exceeded

---

## Practical example

```python
score = semantic_search(query)
if score >= 0.8:
    return semantic_answer
else:
    log_fallback(query, score)
    return llm_fallback(query, timeout=2.0)
```

`timeout=2.0` is the fallback budget.

---

## What to do next

- Start with a single threshold value and log every fallback
- Don’t worry about complex math yet
- Later you can tune the threshold based on actual logs

> In short: threshold = “how sure we need to be”, fallback budget = “how long/costly we allow the fallback to be”.
