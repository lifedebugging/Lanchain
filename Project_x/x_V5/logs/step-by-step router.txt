 The Decision Logic (V5 Production Plan)

For Janus V5, you are implementing a Waterfall Router. Hybrid RRF is over-engineering for 5-10 categories.

The Pipeline:

    Input: Receive raw_query.

    Normalization: Generate clean_query (NFKC + Lowercase + Trim).

    Language Check (Fast Exit): FastText detects if query is English.

        No? -> LLM Router Fallback.

    Keyword Layer (BM25): Run clean_query against the registry.

        Confidence > Threshold (e.g., 0.85)? -> EXIT & ROUTE.

        Low Confidence? -> Proceed to Step 5.

    Semantic Layer (all-MiniLM-L6-v2):

        Calculate Cosine Similarity between query embedding and pre-computed category embeddings.

        Similarity > Threshold (e.g., 0.70)? -> EXIT & ROUTE.

        Ambiguous/Low Score? -> Proceed to Step 6.

    Final Fallback: Call LLM with a list of categories to decide intent.


Step-by-Step Build Order
DAY 1 — Input Layer

Goal:
normalize input BEFORE routing.

Pipeline:

raw query
↓
lowercase
↓
trim spaces
↓
remove duplicate punctuation
↓
store normalized query

Output:

{
  "raw_query": "...",
  "normalized_query": "..."
}

DONE.

Do NOT overbuild this.

No crazy NLP preprocessing yet.

DAY 2 — Fast Rule Router

This is:

keywords
regex
deterministic routes

ONLY for:

greetings
explicit commands
dangerous queries
very obvious intents

Output should NOT be:

"coding"

Output should be:

{
  "intent": "CODING",
  "confidence": 0.91,
  "reason": "keyword_match",
  "matched_keywords": [...]
}

IMPORTANT:
This layer can also return:

NONE

if confidence weak.

That’s GOOD.

DAY 3 — Semantic Router

This becomes:

fallback semantic layer

NOT replacement.

Build category descriptions

NOT:

CODING

Instead:

Questions related to programming, debugging, APIs...

Embed:

category descriptions
NOT category names
Semantic flow
query embedding
↓
compare against category embeddings
↓
top-k similarity scores
↓
return ranked intents

Output:

[
  {"intent": "CODING", "score": 0.82},
  {"intent": "TECH_SUPPORT", "score": 0.61}
]

DONE.

No LLM yet.

DAY 4 — Confidence Layer

THIS is the real brain.

Now combine:

keyword score
semantic score

Simple weighted scoring:

final_score =
(keyword_score * 0.4)
+
(semantic_score * 0.6)

That’s enough for v5.

DO NOT build crazy ML scoring systems.

Then:

if score > threshold:
    route directly
else:
    llm fallback

DONE.

Simple.

DAY 5 — LLM Arbitration

ONLY triggered if:

low confidence
conflicting intents
semantic ambiguity

Prompt:
STRICT.
CONTROLLED.
JSON ONLY.

Example:

Choose ONE intent:
- CODING
- HEALTH
- FINANCE

Return JSON only.

Output:

{
  "intent": "CODING",
  "confidence": 0.74,
  "reason": "debugging-related query"
}

DONE.

DAY 6 — Execution Planner

This is HUGE.

Router should now output:
NOT just intent.

Instead:

{
  "intent": "CODING",
  "model": "SMART",
  "tools": ["web_search"],
  "memory": true,
  "stream": true,
  "reasoning_depth": "medium"
}

THIS is production routing.

DAY 7 — Logging / Observability

Log:

query
normalized query
keyword matches
semantic scores
final route
fallback usage
latency
model selected
tool usage

DONE.
